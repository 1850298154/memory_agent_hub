## 1. PPO (Proximal Policy Optimization)
PPO 是基于**策略梯度**的在线强化学习（On-policy）。

### 核心截断公式 (The Clipped Objective)
$$L^{CLIP}(\theta) = \hat{\mathbb{E}}_t \left[ \min\left(r_t(\theta) \hat{A}_t, \text{clip}(r_t(\theta), 1 - \epsilon, 1 + \epsilon) \hat{A}_t\right) \right]$$

#### 符号详细拆解与读法：
* **$\theta$ (Theta)**: 读作 /'θeɪtə/。代表当前正在更新的网络参数。
* **$r_t(\theta)$ (Ratio)**: 概率比率。$r_t(\theta) = \frac{\pi_{\theta}(a|s)}{\pi_{\theta_{old}}(a|s)}$。
    * **$\pi_{\theta}(a|s)$**: 模型（Policy）在状态 $s$ 下输出动作 $a$ 的概率。
    * **读法**: Pi of a given s parameterized by theta.
* **$\hat{A}_t$ (Advantage)**: 读作 Advantage hat。优势函数，计算公式通常为 $G_t - V(s)$。
    * 如果 $\hat{A}_t > 0$，说明这个动作比平均水平好；如果 $< 0$，说明差。
* **$\epsilon$ (Epsilon)**: 读作 /'epsɪlɒn/。超参数，通常设为 0.2，限制模型更新的幅度。

#### 例子推演：
假设模型输出一个 Token "Hello" 的概率从 $0.1$ 增加到了 $0.15$（$r_t = 1.5$），且该动作的 $\hat{A}_t = 2.0$（非常出色）。
1.  **左项**: $r_t \hat{A}_t = 1.5 \times 2 = 3.0$。
2.  **右项**: $\text{clip}(1.5, 0.8, 1.2) \times 2 = 1.2 \times 2 = 2.4$。
3.  **取最小**: $\min(3.0, 2.4) = 2.4$。
**结论**: 虽然这个动作很好，但由于 $1.5$ 超过了 $1.2$ 的阈值，梯度被强行限制在 $1.2$ 处，防止模型“用力过猛”导致坍塌。

## 2. DPO (Direct Preference Optimization)
DPO 移除了 PPO 中的 Critic 和 Reward Model，直接利用 Pairwise Data（偏好对）进行优化。

### 核心损失函数公式
$$L_{DPO} = -\mathbb{E} \left[ \log \sigma \left( \beta \log \frac{\pi_{\theta}(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \log \frac{\pi_{\theta}(y_l|x)}{\pi_{ref}(y_l|x)} \right) \right]$$

#### 符号详细拆解与读法：
* **$y_w, y_l$**: 读作 y-winning, y-losing。代表人类偏好的回答和不偏好的回答。
* **$\pi_{ref}$ (Reference Policy)**: 读作 Pi-ref。通常是训练前的 SFT 模型，参数固定。
* **$\sigma$ (Sigmoid)**: 读作 /'sɪɡmɔɪd/。将数值压缩到 $(0,1)$ 区间。
* **$\beta$ (Beta)**: 读作 /'beɪtə/。控制对参考模型偏离程度的超参数（KL 惩罚系数）。

#### Token 级别的推理实现：
在代码实现中，我们需要计算回答中每个 Token 的对数概率：
1.  **第一步**: 输入 Prompt $x$，让当前模型 $\pi_{\theta}$ 和参考模型 $\pi_{ref}$ 分别对 $y_w$ 和 $y_l$ 进行 Forward 计算。
2.  **第二步**: 计算回答的 Log-Probability（对每个 Token 的 Log-Prob 求和）：
    * $\text{lp}_w = \sum_{t=1}^{T} \log \pi_{\theta}(y_w^t | x, y_w^{<t})$
3.  **第三步**: 计算奖励差：
    * $\text{diff} = \beta \cdot [(\text{lp}_w(\theta) - \text{lp}_w(ref)) - (\text{lp}_l(\theta) - \text{lp}_l(ref))]$
4.  **第四步**: $\text{Loss} = -\log(\text{Sigmoid}(\text{diff}))$。

## 3. GRPO (Group Relative Policy Optimization)
这是 DeepSeek 的“成名技”，通过同一 Prompt 生成的一组（Group）回答来互相评价，彻底干掉了 Critic 网络。

### 核心优势公式
$$\hat{A}_i = \frac{r_i - \text{mean}(r)}{\text{std}(r)}$$

#### 符号详细拆解与读法：
* **$r_i$**: 第 $i$ 个回答的 Reward。在 R1 中，这个 Reward 是由规则（如代码测试是否通过、数学结果是否正确）给出的。
* **mean/std**: 读作 Mean 和 Standard Deviation。

#### 彻底实现逻辑（伪代码推导）：


假设你正在训练模型解数学题，Prompt 是 $x$。
1.  **采样 (Sampling)**: 同一个 $x$，模型生成 $G=64$ 个回答（Outputs）。
2.  **打分 (Reward)**: 
    * 如果回答的最终答案对，给 $1.0$ 分；
    * 如果思维链（CoT）中包含特定的 `<think>` 标签，给 $0.1$ 分。
3.  **计算优势 (Relative Advantage)**: 
    * 假设 64 个回答里，有 10 个得了 $1.1$ 分，54 个得了 $0.1$ 分。
    * 计算这 64 个分的均值和标准差。
    * $1.1$ 分的回答会得到正的 $\hat{A}$，对应的 Token 概率会被加强。
    * $0.1$ 分的回答会得到负的 $\hat{A}$，对应的 Token 概率会被削弱。
4.  **KL 散度控制**:
    为了防止模型为了得分而乱写（例如无限重复输出答案），会在 Loss 中加入 $D_{KL}(\pi_{\theta} || \pi_{ref})$。

## 总结：如何从每一个 Token 实现？
无论哪个算法，在大模型训练中，最终都落实到：
1.  **Forward**: 拿到模型对当前 Token 的预测 Logits。
2.  **Log-Prob**: 经过 Softmax 拿到 $P(token)$，取 $\log$。
3.  **Accumulate**: 把一个完整 Sentence 里的 Token Log-Prob 加起来（或取均值）。
4.  **Scale**: 根据 Reward 或 Advantage 对这个 $\log P$ 进行缩放。
5.  **Backward**: 反向传播，更新参数 $\theta$。

**建议**: 如果你想在代码中实现，先尝试 **DPO**，因为它不需要复杂的采样环节，只需现成的偏好数据集。而 **GRPO** 是目前大规模推理模型（Reasoning Model）的最前沿方案，最适合有明确客观判别标准（如编程、数学）的任务。
